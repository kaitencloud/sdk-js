A usage row, as `usage.getByInstance`, `usage.getDetail` and `reportUsage` read it, now types what a current Kaiten server adds to it. `EntitlementUsage` gains three optional members: `source`, the layer that grants the entitlement (`license` or `addon`, an open union), `provenance`, which says where the limit comes from, with the identifiers of the licence entitlement, add-ons and voucher boosts it is made of, and `limitCapExceededOveragePercent`, the allowance of the instance's effective limit (`-1` when unlimited). A server that predates them sends none, and a row built against 1.0 still compiles. The members are optional and may also be `null`: a usage report that the server answers from its journal, because the same `transactionId` was already applied, carries the figures of the first report but not the layers they were computed from, so a replay (`idempotentReplayed: true`) sends `source` and `provenance` as `null`, and the allowance is `null` for a flag or a configuration, which has no value to cap. Narrow `null` as well as `undefined` before reading them: `row.source ?? "unknown"`, or `row.source != null`. `ReportUsageResult` documents what a replay carries. The types `EntitlementProvenance` and `BoostModifierType` are exported.
