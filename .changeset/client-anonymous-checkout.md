`KaitenAnonymousCheckoutClient`: what a browser does for a visitor the vendor's backend does not know yet, who buys a self-serve plan from the vendor's own pages with no account, through the `/public/checkout-sessions` routes of Kaiten servers that ship billing.

- `new KaitenAnonymousCheckoutClient({ apiUrl, publishableKey })` takes a publishable key that has anonymous checkout turned on. A class of its own, apart from `KaitenClient` and `KaitenSessionClient`: it holds two credentials of two classes, and a host that offers no checkout does not ship its code.
- `startCheckout` (`POST /public/checkout-sessions`) takes a Turnstile token, the plan by `priceId` or by `licenseSlug` with a `billingPeriod`, add-ons, a voucher code, the buyer's `email`, a `returnUrl`, a `clientReferenceId` and `dryRun`. It answers a `preview` of what is due, or an `open` session with its `token`, and is typed by what it asks for: `dryRun: true` gives the preview, no `dryRun` the session. `getCheckoutSession` reads a session and `confirmCheckout` confirms it: it completes at once when nothing has to be paid (a free plan, a trial with no payment method) and otherwise answers `requires_payment_method` with the hosted `setupUrl`, then `awaiting_payment` and `completed`. Money is the server's, in the SDK's conventions (`currencyCode`, integer minor units).
- The credential of a session is its `ksc_` token, a bearer credential for that one session (do not log or share it) and a third class beside the publishable key (`pk_`) and the customer session (`kst_`): `isCheckoutSessionToken` and `CHECKOUT_SESSION_TOKEN_PREFIX` tell it apart. The publishable key is sent in `X-Kaiten-Publishable-Key` to the start only, and the token in `Authorization: Bearer ksc_…` to its own session's two routes only; neither is sent with the other, whatever `defaultHeaders` holds, and no cookie is sent. `startCheckout` returns the token on an opened session, as the API does, and the client keeps it as well, in memory and in `sessionStorage` in a browser (memory alone on a server, whose own `sessionStorage` is shared by every visitor), because the payment method setup is a full-page redirect; never in a URL or in `localStorage`. `storage` (the shape of `Storage`, exported as `KaitenCheckoutTokenStorage`) keeps them somewhere else, and `storage: null` in memory alone; one client on a server must not serve several visitors, as it holds the token of every session it started. A session that closes keeps its token for the 24 hours the API still reads it with it, so that a reload shows the outcome of a payment; the client drops it when the API refuses it, after that window, or on `forgetCheckoutSession`.
- `readCheckoutReturn(url?)` reads `kaiten_checkout_session` from the URL the hosted page returns to, and gives the URL without it; `clearCheckoutReturn()` takes it out of the address bar, to be called once the confirm or the read has succeeded. `holdsCheckoutSession` says whether the client can still read a session, and a call on a session it holds no token for rejects with `CheckoutTokenMissingError` before any request. That error never means "start another checkout": the session may have completed while the visitor was away.
- `StartCheckoutInput` is typed as the API asks: the plan is named by `priceId` or by `licenseSlug` with a `billingPeriod` (`CheckoutPriceChoice`, one form and not both), and a real start gives an `email` and a `returnUrl`, which only a `dryRun` leaves out; the compiler refuses the rest, and the double is typed with the same overloads. `checkStartCheckoutInput(input)` runs the client's own shape check on an input, the Turnstile token apart, so that a page can refuse a start before it takes a token from its widget.
- A Turnstile token is single-use, a `dryRun` included, so an input the API would refuse for its shape (no token, both forms of the price, no e-mail or return URL on a real start, a member too long or one the API does not know) rejects with a `TypeError` before anything is sent. A read is sent again after a network failure or a 5xx; the start and the confirm never are, and a confirm is safe to send again by hand. A status the client does not know rejects with a `KaitenError` rather than reaching the host outside the closed unions. `onAuthError` is called for a refused credential (a 401, or a 403 `Auth.WrongCredentialKind`), not for a feature turned off.
- Four refusals have a class of their own, all `KaitenError`s: `TurnstileFailedError` (422 `*.TurnstileFailed`), `TurnstileUnavailableError` (503 `*.TurnstileUnavailable`, with `retryAfterSeconds`), `CheckoutSessionClosedError` (409 `*.SessionClosed`, with `sessionStatus`) and `DueTodayChangedError` (409 `*.DueTodayChanged`). A 429 the API's own code names (`*.RateLimited`) is a `RateLimitedError` and the provider's 503 a `ProviderUnavailableError`, as for the other public routes; a bare 429 from a gateway in front of the API, with no such code, is a plain `KaitenError` with its `status` and `retryAfterSeconds`.
- `KaitenAnonymousCheckoutClientLike` is its interface, and `createMockKaitenAnonymousCheckoutClient` of `@kaitencloud/client/testing` its double, which checks the input as the client does and plays a payment that fails or needs the visitor, an expired session, a trial used up meanwhile and a failure of one call. `KaitenClientLike` gains no member, so 1.0 doubles stay valid.
- The catalogue maps what the key can do: `catalog.capabilities.anonymousCheckout` and `turnstileSiteKey`, the site key of the Turnstile widget. They go together (`anonymousCheckout` is true only with a site key) and are `false` and `null` on a server that predates the feature. `BillingCapabilities` gains the two as optional members.
- Bundle: the four refusals above are read by every client of the package, which grows by about 130 bytes gzipped; the anonymous checkout client is 9 768 bytes gzipped on its own (its budget in the repository is 10 100).
- The hook of `@kaitencloud/react` that drives this client, `useAnonymousCheckout`, names the price a visitor chose `selection.licensePriceId` and tells the page the checkout completed with `onSubscribed`, the words `useCheckout` uses (they were `priceId` and `onComplete`): a rename made before `@kaitencloud/react` 1.0.0, which is not published yet, and so breaks nobody. `AnonymousCheckoutFlow` of `@kaitencloud/react-ui` takes `onSubscribed` too. This client's `priceId` is the API's word and stays: the hook maps `licensePriceId` onto it.
